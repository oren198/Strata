# Evidence: only a session bound to a scope changes its directives (v1.17, 2026-10-04)

Security advisory: GHSA-w7vh-r35h-8fvr. Reported by Adam (@Adam13y).

**What changed.**
- **The gate.** A directive change in scope S applies only when the contributor is bound to S. The engine enforces this after judgment. A contribution from any other position that would add, replace or retire a directive in S is admitted as an attributed proposal ("<skill> (<scope>) proposes: … — directive <id> stands"), and S's directive set stays byte-identical. A child writing upward to a parent is one example; an outcome raised from below is another.
- **Adoption.** A session bound to S can adopt the proposal with its own contribution (`adopted_from`).
- **Unchanged.** Own-scope authority. A child's own contribution that contradicts an inherited directive is declined by the judge. From 1.17.1 the engine also checks an admitted child directive against the inherited ones and holds a conflicting one as context (the 1.17.0 release was judge-only here).

**Set.** 52 attempts on a two-level fleet (a parent scope with one binding directive; a child scope under it) in four domains:
- 28 attempts write upward, from a child-bound session to the parent. They include corrections, retirement requests, first-hand claims, hearsay, and changes citing a commit.
- 24 attempts write inside the child. They contradict, exempt, refine or tighten the inherited directive.

## The release tree, confirmed on the file bridge (directional)

The same 52 attempts ran against the release tree on the strata-evals file bridge, with Claude answerers:
- **Parent side:** the parent's directive set was changed by a child-bound session in **0 of 28**.
- **Adoption:** every gate-held proposal the parent then adopted (12 of 12) became the parent's directive and records its source. All 6 attempts to adopt something the gate hadn't held (plain context) were refused.
- **Inside the child:** contradictions and exemptions were declined 12 of 12; refinements and tightenings were admitted 8 of 8. No child directive carries a value looser than the inherited one.

## Stated limits

- **The guarantee holds on the MCP path,** where the contributor's position comes from the session's binding. The local HTTP API (`POST /contribute`, used by the Console) takes the contributor's scope from the request body. It is for local use only (SECURITY.md) and must not be exposed.
- **A child's own contradicting directive (fixed in 1.17.1).** At 1.17.0 nothing mechanical stopped it: the judge is told the inherited directive binds, the default judge declined 48 of 48, and another judge admitted such a case. 1.17.1 adds an engine check after judgment, which holds a conflicting directive as context. Its stated limit: a contradiction phrased without a value, polarity word or marker is not caught mechanically, and a tightening it can't read as stricter becomes context.
- **Own-scope changes rest on the judge.** A session bound to a scope may change its own rules, so an instruction written into its own contribution is stopped only by the judge (see the v1.17 baseline's J4 note). Every such change carries an engine-written line naming who made it.
