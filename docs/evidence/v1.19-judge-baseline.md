## What the fail-closed fix changes
- **Before:** a 429, 5xx, timeout or connection error on the relation re-ask (#242/#243/#244) was read as an unreadable answer. That fails open.
- **Now:** the re-ask is retried with backoff. If it still fails, the contribution is not admitted and the publication is not published. The failure is recorded as a judge failure, so the item waits unjudged and can be retried, the same as with an unreachable judge.
- In the live check above no transport error landed on a re-ask, so the held path was not exercised live; the engine's tests cover it.

## Stated limits carried into v1.19
- A departure label is restored after a context write. Under a tight summary budget, however, the rest of a note can still be reworded. This release does **not** claim that the newest notes survive verbatim.
- `j3-020` and `j1d-032`: as above.
