## Failures / denials

- **Codex sandbox could not execute any shell command** in sessions 2, 4, 6 (and in a pre-run diagnostic): `bwrap: execvp codex-linux-sandbox: No such file or directory`. Root cause: Codex refuses to create its PATH-alias/sandbox helper binaries under a temp-rooted `CODEX_HOME` ("Refusing to create helper binaries under temporary dir /tmp"), and no `codex-linux-sandbox` binary exists anywhere in the npm install to fall back on. This is a direct consequence of the mandated `$W/codex` living under `/tmp/.../scratchpad`. No `--dangerously-*` flag was used to work around it, per the hard rule — noted here instead. Effect on the measurement: codex sessions could still read/contribute via MCP (unsandboxed) and did so, narrating what they *would* do; they just couldn't actually run `git tag`/`pytest`. This did not block the `acted_on` measurement itself.
- `--allowedTools` on `claude -p` is a variadic flag that swallows a following positional prompt; fixed by inserting `--` before the prompt (harness plumbing, not prompt tuning).
- No other permission denials encountered; no live Strata store or `~/.codex/config.toml` was touched (confirmed via `find`/`readlink` before starting, and by using `CODEX_HOME=$W/codex` + explicit `cd $W/proj` for every strata/strata-mcp invocation after an early ambient-cwd `strata-mcp --help` accidentally resolved the operator's real fleet — read-only, no writes occurred).
