## Lessons from v1.15, applied here

These lessons are rules for every item below.

1. **Never put a verdict in an optional judge field.** The measured judge
   (qwen3-235b-a22b-2507) reliably fills `decision` and nothing optional:
   - a sidecar `outcome_disposition` field scored 23/47; moving the verdict into `decision` scored 44/47;
   - `withdraw_published` was omitted every time;
   - #209's `changed_circumstance` and M1's attestation fields were never filled.

   A verdict goes into `decision`. An invariant the theory states is enforced by the engine
   (as with P4 decision A), never hung on a field the judge may omit.
2. **A design note comes before any code** for every engine change. It runs to about 12 lines and
   says who is affected, which record facts change, and what the judge sees. The architect approves
   it first. This caught two over-broad designs in v1.15, and each catch was cheaper than a revision.
3. **The no-regression proof is input identity.** Before a change touches a judge input, capture
   fixtures of the rendered prompt and every tool schema from the base, in a commit of their own.
   Then pin that every path the change does not target is byte-identical. J1/J4 run as noise
   context: every per-item difference is reported in both directions, and any failure is re-run
   on the pre-change build. They are not a pass/fail criterion.
4. **Every merged tree also runs the strata-evals mechanical suite** (docs/releasing.md item 12).
   It is the only check that calls the judge interface from outside the repo.
5. **Report a result the moment it lands.** Attribution follows in a separate message.
6. **Worked examples in judge prompts leak into reasons.** In v1.16 the judge quoted the
   acted_on block's own example ("used port 8443, the service refused") as the contributor's words,
   in 14 of 20 reasons. The ADR 0016 conduct example measured 10/10 on the item worded like it and
   8/10 on a reworded twin. A judge prompt carries placeholders, not concrete worked examples. No eval
   item may share a domain, a name or a phrasing with a prompt example (the strata-evals README
   rule).
7. **Per-item n=10 does not gate a stochastic judge.** The same item on the same build scored 10/10,
   10/10 and then 8/10, and a sibling went from 10/10 to 5/10. Gates are pooled over a class (for
   example 60 reps before and 60 after), reported as a rate with both counts. Every gate report
   records the OpenRouter provider that served the judge: runs are routed across providers (fp8 and
   first-party), and that is a variance source in its own right.
8. **Evidence before claims.** Every number a public claim uses lives in `docs/evidence/` before
   the claim is made, and each wording claim names the test that pins it.

Every item has a 3-revision bound. The philosopher checks the contract lines of P5–P7 before
any code, as was done for ADR 0017.

### 2. #221 — relayed copies (developer)

Build the depth-2 relay eval item (**decided:** the owner corrects a published claim, a child
relays it verbatim, and the grandchild holds the copy) and a Strata pin.

**Decided (CEO):** the engine sweep also runs on a `claim_corrected` refresh that writes **no**
amendment. It is the same invariant as P4 decision A: a scope whose input says a claim is wrong
must not keep publishing it verbatim.

Acceptance:
- the grandchild gets exactly one `claim_corrected` under the original change id;
- fixpoint damping still holds for every other kind.

### 3. P5 — directive consequences go upward

Today, a failed outcome on a directive is accepted as context and goes nowhere. P5 makes the
**engine**, not a judge field, raise it to the scope that **issued** the directive:
- as an ordinary upward contribution, judged there with the reporter's provenance;
- or, for an operator directive, into the operator's view.

It is bounded to once per outcome. The directive is never weighed down (Concept 6). Nothing
binding erodes quietly; the issuer revises through the ordinary channel, or doesn't.

Eval: ol-010's routing half becomes scored, and a new item covers an operator directive.

### 4. P6 — decay by condensation order

1. **Engine side, first.** The #202 condensation signal records, for each dropped item, whether
   it was corroborated, corrected or unexamined at the time. The order becomes visible in the record.
2. **Judge side.** The condensation rewrite prompt lists each carried item's corroboration, and
   says to drop **unexamined** before **corroborated**. This deliberately changes the condensation
   input, so the proof for that path is a new eval: an over-budget scope where unexamined context
   is dropped before corroborated context, at 10 reps. Identity is pinned for every other path.

The wording is "unexamined", never "poorly standing".

### 5. P7 — ratification reads standing

The ratification prompt shows each candidate's **derived** standing: the corroborating outcomes,
their reporters' scopes, and whether they are independent of the item's source. The hazard items
gate it:
- a restatement is not corroboration;
- reasons that embellish evidence (the ol-007 pattern);
- one scope's standing is not reach (5b / ol-009 becomes executable).

This is the largest judge-side risk, so it comes last. **If P5/P6 use up the bound, P7 moves to
v1.17.** The CEO accepted that in advance, and the architect says so as early as it is known.

### 6. #219 — paraphrased publications (a paper spike)

A design note only, and a build only if it is cheap. The candidate: at publish time, the
**engine** records which context claims a published item came from, so a correction can find a
paraphrased copy by id rather than by content. If this needs a new judge input, it waits for
P7's measurement discipline.

### 7. Codex adoption (when unblocked)

The root cause of #218 is that Codex refuses helper binaries under `/tmp`.

**Decided (CEO):** use a dedicated `CODEX_HOME` under `~` (e.g. `~/.strata-eval-codex-home`),
created per run and **removed after each run** so nothing is left behind. The real `~/.codex` is
never touched, and auth is symlinked as before.

Then re-run the six-session adoption protocol for Codex, both before and after the item-id
listing, so the numbers are comparable with Claude Code's 0/6 → 6/6.
