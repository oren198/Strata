# V1.11 cycle plan — publication as the sharing channel

*Written 2026-08-31. Anchor: issue #168. Version target: **1.11.0** (minor —
the anchor changes the perspective payload's meaning; 1.10.x was patch churn).*

This is a cycle plan, not a design. Per `ROADMAP.md`, each direction below is
picked up as: grill the foundations → ADR if the bar is met → testable feature
branches → build → review → merge.

---

## Theme

The 1.10.x line hardened the **install and binding** surface (register/doctor,
soft-start, self-bind guard). The open issues cluster somewhere else entirely:
what a scope *shows other scopes*. Five open issues (#168, #143, #128, #135,
#169) are all about the publication face, and the most recent operator-raised
architectural objection (#168, 2026-08-29) is that chain inheritance bypasses
that face completely.

So: **make publication the single, judged, bounded channel for non-binding
knowledge — and close the gaps in the mechanism that already exists.**

## Tier 1 — Anchor: ADR 0013 (#168 with #173) — **grilled 2026-08-31**

The grill is done. `docs/adr/0013-publication-as-the-only-sharing-channel.md`
is written (**Proposed**) and carries the seven decisions:

| | Decision |
|---|---|
| D1 | Chain edges carry **directives only** — full walk, every ancestor. Raw context never leaves its scope |
| D2 | Publication is the single sharing channel; **one face** for peers and descendants alike |
| D3 | Publication travels **exactly one edge** — chain or reference. Each stratum becomes a curation checkpoint |
| D4 | Republication **preserves provenance transitively** ("according to root, via parent"); non-corroboration extends with it |
| D4b | A withdrawn item **takes its relayed copies with it**, mechanically — a fourth ADR 0007 D3 choke point |
| D4c | The judge **sees that an item is second-hand**, and that origin is information, not permission |
| D5 | Operator memory **collapses to directives only**; operator stays exempt from D2/D3 |
| D6 | Enforcement: `register` seeds **harness deny-rules** for `.strata/`; obfuscation and relocation rejected, with reasons |
| D7 | **No migration** — stored state is never rewritten; new rules govern acts from the release forward |

Remaining Tier-1 work:

1. **Accept the ADR.** It is Proposed with no open questions — every branch
   was resolved in the grill, so acceptance is a review, not research.
2. **Apply the CONTEXT.md edits** the ADR's Consequences section enumerates.
   Deliberately *not* done yet: the glossary describes the running system, and
   the ADR is not accepted. It changes on acceptance, not before.
3. **Implement the composition change** — a feature branch, only if the ADR is
   accepted early enough in the cycle; otherwise it opens 1.12 with the design
   already settled.

## Tier 2 — Publication mechanism gaps (independent of the ADR)

These are gaps in the publication machinery **as it exists today**. They do not
wait on Tier 1, and ADR 0013 makes every one of them more load-bearing, not
less: publication is now the *only* sharing channel.

- **#143 — `judge_publication` is blind to operator memory.** ADR 0013 D4c
  adds a relay-origin input to the same prompt — do both as one change. An operator
  directive binds what enters the summary but not what leaves as the
  publication. Thread `operator_memory_binding(...)` into `judge_publication`
  the way `app.py` already threads it into the single and batch contribution
  paths. Smallest, clearest, highest-consistency win in the cycle — do it first.
- **#128 — publication judging has no attempt machinery.** A failed
  `judge_publication` strands silently and is indistinguishable from an
  unjudged act. Apply the #118 pattern: attempt row, explicit terminal marker
  (no LLM in the marker path), state exposed on the read surfaces. Existing
  stranded acts stay as they are, documented (append-only holds).
- **#135 — publication budget.** `Σ Pubⱼ` is the only term in the perspective
  size equation with two unbounded factors. Bound the face the way
  `summary_max_words` bounds the summary. **ADR 0013 D3 shrinks this**: with
  publication travelling one hop, chain depth leaves the size equation and the
  budget bounds one face against its readers rather than a depth product.

## Tier 3 — Read-side trigger

- **#177 — `SessionStart` hook for Claude Code.** The write side learned this
  lesson already (the Stop hook exists because prose wasn't enough); the read
  side has no equivalent trigger. Cheap, local, symmetric with the existing
  hook. Hard constraint from the issue: the hook is a **trigger, not a
  delivery channel** — it must never inject memory content, which would bypass
  binding, scoping and judgment.

## Tier 4 — Console (operator decision, 2026-08-31: in)

Horizon 4's "UI write endpoints → Command & Control" arc, pulled into this
cycle deliberately.

- **#170 — fleet editing.** Implementation plan already written
  (`2026-08-26-console-fleet-edit.md`); its Feature-A/live-reload half shipped
  in 1.10.3, so the reload task is done and the editor UI + save endpoint
  remain: raw-YAML editor, server-side validation through the same code as
  `strata bootstrap`, save = validate → backup → atomic write → hot-swap,
  content-etag conflict guard. Independent of the Tier-1 ADR — start here.
- **#180 — operator memory editing.** `operator_supersede`/`operator_retire`
  already do in-person summary correction (append to the target scope's record,
  mechanical splice, no LLM, publication propagation under the same lock) and
  are reachable over HTTP — nothing drives them from the Console. Summary level
  only; the record stays append-only. Design against ADR 0013 D5.
- **#169 — publications browser.** What a scope currently publishes, its
  publication acts history, and what a given reader receives through reference
  edges. **Sequence after the Tier-1 ADR**: if publication becomes the single
  sharing channel, "what a reader receives" is exactly what the ADR redefines,
  and building the browser first means building the wrong view. Design it with
  the ADR's answer in hand.

Related but **not** in this cycle: #109 (agents forget to contribute) — the
close-out tool shipped; leave it to accumulate live evidence before adding
more machinery.

## Recommended order

**#178 → rest of Tier 0 → accept ADR 0013 → #143 → #170 → #128 → #177 → #180 →
(ADR-dependent: #135, #169, composition change)**

Rationale: #178 first because it silently destroys the thing the product
exists to keep. ADR 0013 is already grilled, so acceptance is a review, not a
research task — and it gates the largest downstream decisions. #143 is a
one-parameter consistency fix that ADR 0013 D2 makes more urgent, not less: if
publication is the only sharing channel, a judge blind to operator memory
means operator directives constrain nothing a scope tells anyone. #170, #128,
#177 and #180 are independent of the ADR and fill the implementation window;
#169 and #135 land after it, because D3/D4 redefine exactly what they render.
