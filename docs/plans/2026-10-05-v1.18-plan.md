# v1.18 plan (DRAFT, for the operator)

Status: draft on `docs/v1.18-plan`, not merged. Scope and order are the operator's call.

**Theme (operator, 2026-10-05).** v1.17 defended a parent against its children: the position gate (1.17.0) and the admit-side inherited check (1.17.1). **v1.18 defends an inherited rule inside the child's own scope**, on every path an exception can take: a context item, a publication, and rewording down a chain. Anything that doesn't serve that theme moves out (section 4).

Method, as in v1.17:
- a design note before code;
- the philosopher's line before any new admission rule;
- a forged-answer attack on every mechanical verifier, run in both directions (exceptions held, legitimate items passed);
- gates on the strata-evals file bridge (Claude answerers, directional);
- a pinned-judge measurement only in the release baseline.

## 1. The three theme issues, in order

**First: #244, the three-level drift eval (measure before building).**
- **Why first.** It is the gate for #242 and #243 as well. It measures how far today's 1.17.1 check already holds, so the work after it targets measured gaps, not guesses.
- **Set.** A grandparent rule, a child exception and a grandchild adoption. The exception passes down by publication and is paraphrased at each step. It covers:
  - plain and reworded wording;
  - directive and context forms;
  - parent rules that carry a value, a polarity word or a marker, and weak parent rules that carry none;
  - legitimate tightenings and refinements as twins that must pass.
- Labelled blind by the philosopher. Public in strata-evals; no outside party's texts.
- **Then the matching.** Improve "same subject" beyond the leading-noun-phrase match, measured on a held-out split. Decide, with the philosopher, what happens when the parent rule is weak: today that rests on the judge.

**Second: #242, child context that undercuts an inherited directive.**
- **Philosopher first:** the contract line between an exception (a contrary rule held as context) and a consequence report (evidence that following the rule went wrong). Under the 2026-09-24 ruling, a consequence report is admitted and raised to the issuer.
- **Then:** extend the 1.17.1 check to context admits. An exception is held or declined with an engine note. A consequence report passes and is raised, as today.
- **Gate:** #244's context form, plus a consequence-report twin set (must pass and be raised); a forged-admit attack on context; the outcome_loop suite unchanged.

**Third: #243, a publication that carries an exception down.**
- Apply the same check (directives, plus #242's exception rule) to items a scope publishes, against the directives the publisher inherits. An exempting or contradicting publication is refused with an engine note.
- It reuses #242's line and #244's chains: the publication path is exactly how the drift eval moves an exception down.
- **Gate:** #244's publication chains; the P1 publication-fidelity and P4 echo suites unchanged.

**Fourth (core, after #242 and #243): what an applied fleet change owes (#247's core half).** GrokBot builds the peripheral half of #247 (propose / apply / reject, the two flags, the delegation refusal). Its apply only writes `fleet.yaml` and records an operator act carrying the change type and the before/after topology. The core half emits from that record. The philosopher's line (2026-10-07): a structure change owes notice exactly where it changes what binds a scope, or cuts a channel a live attribution depends on; everywhere else, the next read is the notice.

| Change | Owed |
|---|---|
| Reference edge added | nothing |
| Reference edge removed | an evidence notice to the reader: its items attributed to that source can no longer be kept live; its own judge re-grounds them or lets them fade; nothing is corrected |
| Scope removed | the same notice to every reader of its publication; if it was on a chain, a refresh for every descendant (directives that bound them stopped binding: an authority's act, a legitimate refresh input) |
| Chain edge changed (re-parenting) | a refresh of the moved subtree against its new inherited directives; any own directive that now contradicts one is SURFACED to that scope's own sessions and the operator, never auto-retired (position gate) |
| Description changed | nothing; relevance is judged against it from then on |

Design note first (new change-event kinds versus reusing the existing ones; how a re-parent refresh surfaces conflicts using the 1.17 inherited check). Gate: a fleet-change scenario suite on the bridge.
